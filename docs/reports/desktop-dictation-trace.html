0Read the trace

The time origin is session open

T0 = openSessionTrace() during the IDLE → STARTING snapshot. Input handling, start admission, and the synchronous prefix of transcription.open() happen before this anchor.

offset = timestamp − T0

T0 is not physical key-down, mic acquisition start, or recording-live. UI buttons and hands-free toggles can also start a session.

PostHog receives a summary

The client collects named spans, synthetic durations, points, and chunk statistics. At flush it builds one flattened event. Raw startedAt, endedAt, span IDs, and the span tree are not included in that event.

duration = span end − span start

A 261 ms mute_duration_ms says how long the phase took. It does not locate its start or end relative to the shortcut.

Illustration, not a sampled production trace. The waterfall and example payload below use deliberately constructed times to show ordering and overlap. They are not cohort percentiles. Section 4 contains the separate local measurements.

Scope: a successful live dictation with sounds enabled and automatic paste. The native audio detail is the current macOS AVAudioPlayer implementation. The AVAudioEngine experiment is not part of this flow. Other outcomes and draft mode are covered in section 6.

2.1 · What the startup audio gate actually waits for

Recorder.start() immediately sets beepPending = true. Main reads preferences and sends startRecording. On macOS the helper serializes ambiance operations, waits for rec-start playback completion, calls the system-mute setter if enabled, and replies. The promise then releases the gate.

Non-final frames are dropped while the recorder is still starting or the startup audio gate is closed. First-PCM liveness is measured before these checks. A final frame bypasses the startup audio gate, but not the recorder-starting check. If dictation sounds are muted, the gate releases after reading preferences without waiting for the native RPC.

The mute setter returning successfully does not prove physical silence. The implementation does not wait for a CoreAudio property-change notification.

2.2 · Resolution and backend time

resolve.drain waits for already admitted chunk work. resolve.flush then obtains the transcription lock and flushes the provider. For cloud dictation, this can include waiting for a backend final result and cloud formatting. resolve.format prepares the returned text and may perform additional configured formatting.

resolve_duration_ms covers this whole chain plus other work in the resolve effect. It is not a pure server-latency metric. Provider warmup and server-internal spans are not separately exported by this desktop event.

3What reaches PostHog

Event: transcription_completed_v2. Ten named phase durations, a separate session duration, and four offset fields can be emitted. Fields are conditional on which work ran and finished in time; a missing field is not zero.

6Branches and trace-flush rules

      
The lifecycle ends before every tail must end
The root duration stops when the public state returns to idle. Telemetry waits for registered obligations, including recorder closure, storage, native audio restoration, and a dispatched paste response.
Flush occurs once: when the root is closed and all expected obligations settle, or after a 15 s grace period from root close. Late records after flush are dropped. Shutdown force-flushes remaining traces.
Presence does not always prove success
An Effect span may end with failure or interruption and still supply a duration. Some best-effort spans catch their own errors. By contrast, delivery.pasted is recorded only for a confirmed successful native paste.
The flat payload takes the first mapped duration/offset for each key. Individual span status and timestamps remain in internal/debug records; failure attribution is summarized separately.

      
6.1 · Quick release, cancel, empty, and failure
A quick release or interrupted start can seal a discard before usable audio exists. Empty, dismissed, failed, and discarded sessions still go through settlement and emit the session summary if the app gets to flush it. An admission refusal before session creation does not create this trace.
Capture failures and provider terminal failures can seal the result during STARTING or RECORDING. The happy-path finalization and paste spans may therefore be absent. Cancellation can retire chunk work before late timings finish.

      
6.2 · Draft mode and post-session actions
On stop, draft mode may wait for a bounded clipboard-copy capture barrier of up to 2.5 s before entering the measured transcription.resolve effect. That wait is not a dedicated exported timing.
Successful draft sessions stage text for review instead of immediately pasting. The later “confirm draft” paste and “paste latest transcription” action are outside this live session's delivery.pasted timing.

      
6.3 · Two different drains
The renderer/recorder drain flushes the worklet, accepts final in-flight PCM, then emits recorderClosed. There is no dedicated PostHog duration for that stop-to-close-decision interval.
resolve.drain begins after that decision and waits for chunk-processing tasks already admitted to transcription. recorder_close_duration_ms is another distinct measurement: the asynchronous WAV write/finalize/enrichment tail, which may overlap resolve.

The existing session root is retained as the lifecycle envelope. It starts at T0 and ends at idle; outstanding native responses and other obligations can end after it. Parent and child intervals overlap, so their durations must not be added.

    

    

      
9Names and clocks — simplified contract

      
Measure existing operations first. Native RPCs are measured entirely in main. Native code, response contracts, and generators are unchanged. Internal playback/mute subphases are deferred until later analysis justifies them.

      
9.1 · Interval attributes

      
name              dotted namespace + hyphenated operation
span_id           unique within the event
parent_span_id    logical parent
process           main | renderer
start_offset_ms   epoch start timestamp − session-open epoch timestamp
duration_ms       elapsed milliseconds
status            ok | failed | interrupted
chunk_index       present for repeated chunk work

      
9.2 · Clock sources

      
Cross-process starts use Date.now() Unix-epoch milliseconds. Main and renderer share the machine's wall clock, so their offsets need no clock mapping. Local performance.now() and existing Effect timers supply elapsed durations where already used. Existing synthetic main spans can use Date differences.

      
start_offset_ms = startedAtMs − sessionStartMs

      
Renderer timing batches contain only phase name, epoch start, and elapsed duration for completed operations. The original cached-config query is retained. There is no clock-sync endpoint, uncertainty metadata, clock-change correction, or native timing payload.

      
9.3 · Measurement scope

      
  • The session anchor remains session open, not physical shortcut press. Early provider warmup can have a negative offset.
  • Native RPC duration includes transport, scheduling, playback and mute work inside that RPC. It does not isolate those internal parts.
  • A helper reply does not establish acoustic silence or visible text insertion in another application.
  • The local measurements in sections 4 and 8 remain historical evidence, not results from this change. Unmeasured internal work remains unmeasured.

10.3 · Coverage and limits

      
  • Native startRecording and stopRecording use their original requests and responses. Main records call start and elapsed time. No native subphase timestamps are returned.
  • The 12 selected additional spans are kept even when fast. Added operation timers record successful completions; a failed operation has no duration for that operation. Existing failure reporting and lifecycle spans remain. Completed VAD/provider work and lock waits are retained above 20 ms, capped at 64 per session with a dropped count. Full-session aggregates remain available.
  • Completed startup timings piggyback existing renderer reports, including completed steps before a later capture failure. First-frame reports and the final completion batch are nonblocking. Capture cleanup is not timed. Format metadata sent with audio is retained as its latest value, not expanded into per-frame trace points.
  • The existing 15 s telemetry grace bounds late reports after lifecycle idle. Incomplete obligations are listed without fabricated completion times.
  • Paste confirmation retains its existing meaning: native acknowledgement, not observed insertion.
  • No transcript, audio, clipboard/window text, device identifier, email or credential is added to these timing properties.
